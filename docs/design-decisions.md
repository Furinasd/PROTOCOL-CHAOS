# Design Decisions · 从假设到证据

整理日期：2026-09-12。下述实现事实来自源码与配置；体验理由来自作者设计记录，未经本次真人试玩复现。

## D01 · 为弹刀设置资源前置条件

**问题：** 免费且高收益的防御可能削弱其他行动的价值。

**选择：** 能量上限 3；同色吸收 +1，规避 +2，异色弹刀 -3。理论上形成三次吸收、规避加吸收、两次规避等不同路径；容量也使过量充能产生溢出。

**代价：** 玩家同时处理颜色、时机与资源。连续吸收仍可能构成低位移策略，因此“鼓励攻防切换”是设计目标，“已消除原地最优解”不是当前证据结论。

**下一实验：** 在相同敌人与配置下比较自由移动和尽量不主动位移的策略；记录完成时间、受伤、充能来源与失败原因，不把个体探索性结果泛化为统计结论。

来源：[资源系统](../Assets/Scripts/Player/PlayerEnergySystem.cs)、[受击逻辑](../Assets/Scripts/Player/PlayerCombatReceiver.cs)。

## D02 · 教学暂时补充资源，保留真实消耗

**问题：** 首次接触弹刀时，缺能可能掩盖 Timing 学习。

**选择：** Phase 2 在前摇时补满能量，仍让成功弹刀消耗 3 格。Phase 3 清空能量，恢复完整充能路径。

**代价：** 自动注能可能形成对免费资源的依赖；通关计数不等于理解。Phase 3 也不强制使用所有充能方式。

**下一实验：** 无口头指导的首次玩家测试，观察 Phase 2→3 的迁移，询问能量不足时为何失败；同步覆盖 Phase 2 两次真实弹刀及重复结算问题。

来源：[流程配置](../Assets/Scripts/Systems/Core/QuestFlowManager.cs)。

## D03 · 撤下全场净化，保留技术管线

**问题：** 作者调试复盘认为，一次高光反制清空场地会过快解除环境压力。

**选择：** 保留 `PuddleManager.OnGlobalPurify`、订阅与动画，但删除异常核心弹刀的调用。

**实现证据：** [f0a647b 删除触发](https://github.com/Furinasd/PROTOCOL-CHAOS/commit/f0a647b)。这证明代码变更，不独立证明试玩收益；暂无量化前后对照。

**连带代价：** 常规回池仍依赖净化，撤下触发后需要独立生命周期预算。下一步比较数量上限、有限寿命或阶段回收，不默认恢复全场净化，也不同时加入多个规则。

来源：[PuddleManager](../Assets/Scripts/Environment/PuddleManager.cs)、[ChaosPuddle](../Assets/Scripts/Environment/ChaosPuddle.cs)。

## D04 · 单场景与几何体限制

**选择：** 用几何体变形、颜色、前摇、声音与顿帧表达战斗；使用场景模板与事件推进四阶段，优先完成可交互规则。

**代价：** Inspector 覆盖与查找兜底增加隐式依赖；动态机位、部分音效和终幕资源没有完整装配。极简美术减少资源制作量，但不能替代可读性验证。
